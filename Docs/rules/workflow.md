# Процесс, пайплайн и ревью

- Перед планом осмотри текущее состояние. Обозначь допущения и выясни существенные детали до изменения затронутой системы.
- Работай в согласованном объёме. Смежный рефакторинг, редизайн или изменение механик требуют отдельной причины и задачи.
- Если новые данные меняют подход, объясни причину и обнови план до правок в новом объёме. Используй порядок согласования из [AGENTS.md](../../AGENTS.md).
- При сохранении сцены сохраняй чужие несохранённые правки. В Git добавляй только файлы задачи. Сохраняй посторонние изменения в рабочей копии.
- Храни `.vscode`, `.claude`, `Library`, `Temp` и локальные отчёты тестов вне Git.
- В списке сборки соблюдай порядок MainMenu → Level 1 → GameplayLab. Последняя сцена — дополнительный вход для плейтеста. Устаревшие сцены убирай из списка, поскольку установленный Test Framework включает отключённые записи в тестовую сборку.
- Обновляй README и карту архитектуры после значимых изменений. В конце сообщай, что сделано, почему, что проверено и какие ограничения остались.

За инструментами редактора, сборки и устройства обращайся к [стеку разработки](../Development-Stack.md).
