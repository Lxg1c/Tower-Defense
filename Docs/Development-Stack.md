# Технологии разработки Tower Defense

Актуально на 22 ноября 2026 года. Версии пакетов указаны по проекту, версия Unity CLI — по рабочей машине.

## Из чего состоит игра

| Технология | Как используется |
| --- | --- |
| **Unity 6.0 LTS (6000.0.72f1) и C#** | Сцены, префабы и игровой код. Компоненты Unity связывают игровые правила с объектами сцены. Характеристики врагов, построек и волн задаются в ассетах ScriptableObject. |
| **URP 17.0.4 и Shader Graph** | 3D-рендеринг, освещение, материалы, эффекты и разные профили качества для ПК и Android. У игрока есть настройки масштаба рендера, освещения, карт нормалей и SSAO. |
| **UI Toolkit** | Главное меню, HUD, строительство, подсказки, справочник, загрузка и экраны исхода. UXML задаёт разметку, USS отвечает за стили и переходы, C# связывает интерфейс с игрой. |
| **Unity Input System 1.19.0** | Клавиатура и мышь на ПК, касания и виртуальный джойстик на мобильных устройствах. |
| **AI Navigation 2.0.12, NavMesh и физика Unity** | Наземные враги и союзники прокладывают маршрут по NavMesh. Игровой код выбирает цели, а коллайдеры и рейкасты помогают проверять укрытия и попадания. |
| **Cinemachine 3.1.6** | Камера, которая сопровождает игрока. Во время приказа отряду камера отдаляется для обзора карты. |
| **Unity Localization 1.5.14** | Русский и английский интерфейс. Строки лежат в коллекции `Game UI`, C# обращается к ним через `GameLocalization` и ключи из `LocalizationKeys`. |
| **Unity Audio** | Две потоковые дорожки: спокойная для меню и строительства, боевая для волн. `BackgroundMusic` делает плавные переходы, `GameAudioSettings` хранит настройки громкости. |
| **PlayerPrefs** | Локальные сохранения прогрессии и пользовательских настроек. Прогрессия сериализуется в JSON. |

Точные версии и транзитивные зависимости зафиксированы в [манифесте пакетов](../Packages/manifest.json) и [файле разрешённых зависимостей](../Packages/packages-lock.json). Где искать код конкретной системы, описано в [архитектуре проекта](Architecture.md).

## Как Codex работает с Unity

| Инструмент | Роль в разработке |
| --- | --- |
| **Codex** | Читает и меняет C#, разметку и документацию, запускает команды, проверяет результаты тестов и сборок. Маршруты к правилам указаны в [AGENTS.md](../AGENTS.md). |
| **Unity Pipeline (`com.unity.pipeline` 0.7.0-exp.1)** | Пакет в проекте. Запущенный Unity Editor через него принимает команды по локальному HTTP API. Он позволяет проверять консоль, запускать Play Mode, импортировать ассеты, работать со сценами и префабами через API редактора, запускать тесты и сборки. |
| **Unity CLI (`unity` 1.0.0)** | Командная строка на рабочей машине. Это основной способ, которым я обращаюсь к Pipeline в этом проекте. CLI находит открытый проект, отправляет команды и возвращает структурированный результат. |
| **Unity MCP (`unity mcp`)** | Встроенный в Unity CLI сервер для AI-клиентов с поддержкой Model Context Protocol. Он представляет команды редактора как MCP-инструменты и обращается к тому же Pipeline. В этой сессии для Unity использовался прямой вызов CLI через PowerShell. MCP доступен как альтернативный интерфейс. |

```text
Codex → PowerShell → Unity CLI ────────────┐
AI-клиент → Unity MCP (unity mcp) ─────────┴→ Unity Pipeline → Unity Editor
```

Здесь Unity Pipeline — автоматизация редактора. URP относится к отрисовке игры, а устройство и установка APK проверяются отдельно через ADB. [Unity Pipeline](https://docs.unity.com/en-us/unity-cli/unity-pipeline/unity-pipeline-package) · [Unity CLI и MCP](https://docs.unity.com/en-us/unity-cli/replace-mcp-server-unity-cli).

Примеры команд для установленной версии Pipeline. Запускаются из корня проекта при открытом Unity Editor.

```powershell
unity status --format json
unity command console_status --caller plugin --skill unity-pipeline --format json
unity command run_tests --mode playmode --async_tests true --caller plugin --skill unity-pipeline --format json
unity command test_status --caller plugin --skill unity-pipeline --format json
```

## Макеты, сборки и проверки

| Инструмент | Что им делаем |
| --- | --- |
| **Penpot и Penpot MCP** | Сравниваем и правим макеты мобильного и настольного интерфейса. Затем переносим согласованные элементы в UXML и USS. Penpot MCP обращается к дизайн-файлам, Unity MCP — к редактору. |
| **Unity Test Framework 1.6.0 и NUnit** | Edit Mode для правил и конфигурации, Play Mode для поведений в запущенной сцене. Примеры проверок — цены и списания, препятствия для выстрелов, переходы окон и смена музыки. |
| **Unity Profiler и Frame Debugger** | Profiler помогает разбирать затраты в кадре. Frame Debugger показывает события отрисовки, например проходы теней и глубины для SSAO. |
| **Встроенный бенчмарк и Android Perfetto** | Встроенный тест сравнивает количество моделей и бой с башнями, собирает FPS, время кадра и число вызовов отрисовки. Perfetto показывает системную сторону, в том числе интервалы вывода кадров Android. |
| **Android SDK, IL2CPP и ADB** | Unity собирает Android APK через IL2CPP и Gradle. ADB проверяет подключение телефона, устанавливает APK поверх текущей версии, запускает приложение и читает журнал через `logcat`. |
| **Git и GitHub** | История версий, проверка диффов, коммиты и публикация в `main`. Локальные APK, логи и записи профилировщика хранятся в игнорируемых папках. |
| **PowerShell, ripgrep, Python и FFmpeg** | PowerShell запускает и связывает инструменты, ripgrep ищет в проекте, Python помогает с анализом замеров и скриншотов. FFmpeg использовался для подготовки игровых аудиопетель и замера громкости. |

Обычный цикл работы выглядит так: сверить задачу с макетом и кодом, внести правку, проверить её в Unity, затем на целевом устройстве, если она зависит от платформы. Настройка проекта и запуск описаны в [README](../README.md), а продуктовые решения — в [GDD](GDD.md).
